# ファイルパネル — 外のものがファイルの横に座るための口

## 何をしたいか

MulmoTerminal の外にある機能を、Files ペインで開いたファイルの横に置けるようにしたい。たとえば
クライアントのレビューコメント、lint の指摘、翻訳メモ。**どれであるかを本体は知らない。** 本体が
用意するのは受け口だけで、機能はすべて拡張側（ユーザーが持つページとコマンド）に置く。

きっかけは、原稿（Markdown）に付いたクライアントコメントを Cursor 拡張で表示している別プロジェクト。
同じことを MulmoTerminal でやろうとすると、既存の拡張点では足りなかった:

- **コレクションのカスタムビュー**は sandbox の iframe で、自分のコレクションのデータ以外に通信できない。
  エディタの行にも触れない。
- **GUI プラグイン**は `plugins/plugins.json` とフロントの静的 import に焼き込まれていて、足すには
  本体のビルドが要る。出る場所も Canvas で、エディタの横ではない。

## 最初に作って捨てた形

最初は「注釈プロバイダ」として作った。コメントの**出どころ**だけを差し替え可能にし、スレッド・返信・
解決という概念、そのパネルの見た目、エージェントへの依頼文は本体に持たせた。

これは 1 段ぶん具体的すぎた。本体に入るのが「コメント機能」になってしまい、差し替えられるのは
接続先だけ。オープンソースの本体が特定の使い方を抱えることになる。この PR はその作り直し。

## 決めたこと

### 1. 本体が渡すのは 5 つの能力だけ

1. 開いているファイルを知る
2. 行に印を付ける
3. エディタを行へ動かす
4. 自分のコマンドに尋ねる
5. 隣のターミナルの入力欄に文字を入れる

パネルの中身を本体は描かないし、読まない。コマンドの答えも中を見ずにページへ渡す。「コメント」という
語は `common/` にも `server/` にも `src/` にも出てこない。

この 5 つで足りることは、見本（`samples/file-panel/`）で確かめた。コメントの一覧・返信・解決・
エージェントへの依頼が、本体を触らずにページ 200 行とコマンド 80 行で書けた。

### 2. ページは隔離し、外へ出る道はコマンド 1 本

ページは opaque origin の sandbox iframe で、CSP は `default-src 'none'`。fetch も外部スクリプトも
本体の `/api` も使えない。外に出たいときは `request` を送り、本体がそのパネルのコマンドに中継する。

ページに直接ネットワークを許さなかった理由:

- 許すと、ページが読んだファイルの中身をどこへでも送れる。コマンドなら、何を外に出すかは
  ユーザーが読めるコードで決まる。
- 認証トークンをページ（＝ブラウザ）に置かずに済む。

### 3. コマンドは argv で実行。シェルは通さない

カスタムエージェントと同じ規則・同じトークナイザ。`~` も `$HOME` も展開しない。

### 4. 宣言はグローバル設定だけ

`~/.mulmoterminal/config.json` の `filePanels`。プロジェクトの `.mulmoterminal.json` には置かない。

ページは**ファイルを開いただけで読み込まれ**、コマンドも走る。プロジェクトの設定はクローンと一緒に
届くので、そこに置けると「リポジトリを開いたら他人のコードが動く」になる。

### 5. 印は「行と ID」だけ。どの行かはページが決める

本体は版の履歴を持たないので、当て直しはできない。ページ側が「いまのテキスト」に対して行を決め、
本体はそれを読み手のタイプに合わせて運ぶだけ（変更マークの gutter と同じやり方）。運んだ結果は
`mark-lines` でページに返す。

### 6. 出すのは生テキストの横だけ。場所を取るのはページが頼んだときだけ

プレビューは別の文書で、印を置く行がない。プレビュー中はパネルごと外す。

対象の拡張子のファイルを開くと iframe は読み込むが、ページが `show` と言うまで幅は取らない。
「このファイルには言うことがない」パネルが、毎回 340px を取るのを避けるため。

### 7. ファイルが変わったら、本体が先に片付ける

別のファイルを開いたとき、本体はそのパネルの印と表示を消してから、新しい `file` を送る。ページの
応答が遅くても、前のファイルの印が新しいファイルに残らない。

### 8. ターミナルへは「入れるだけ」

`insert` は入力欄に文字を入れる。送信はしない。`@` ボタン（#2575）と同じ経路・同じ規則で、
未保存の編集は先に保存する。

## 触ったところ

| | |
|---|---|
| `common/filePanels.ts` | 契約。設定エントリ、ページと本体のメッセージ、信用しない前提の読み取り |
| `server/files/file-panel-command.ts` | コマンドの実行（タイムアウト 20 秒、出力 8MB まで） |
| `server/files/files-panels.ts` | ページの配信（CSP つき）と、コマンドへの中継 |
| `src/components/cmLineMarks.ts` | gutter の印と行の色。タイプに追従 |
| `src/components/FilePanelFrame.vue` | 1 パネル分の iframe と、メッセージの出入り |
| `src/components/FilePanels.vue` | パネルの列 |
| `src/composables/useFilesPanePanels.ts` | ペイン側の配線 |
| `samples/file-panel/` | この口だけで作ったコメントパネルの見本 |

`FilesPane.vue` は行数の上限（600）ちょうどだったので、競合バナーを `FilesConflictBanner.vue` に
切り出して場所を作った。動きは変えていない。

## やっていないこと

- **Settings の UI。** エントリは読み込むページと実行するコマンドなので、手かスキルで書く。
- **ページからファイルを書き換える操作。** 人かエージェントが書く。
- **エディタ内への描画**（行間のウィジェットなど）。gutter の印と行の色まで。
- **パネルの幅の設定。** 340px 固定。
- **ページへのトークン付与。** iframe が自分で別のページに遷移すると、そのページも同じ窓から話せる。
  Markdown プレビューはこれをトークンで防いでいる（#2515）が、あちらは「誰も検査していない文書」で、
  こちらはユーザーが自分で宣言したページなので、同じ信頼の置き方にはしていない。
